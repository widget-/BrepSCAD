## Compatibility measurement

Before changing the language, the evaluator was run over 109 `.scad` files from
BOSL2 and MCAD. Only 35 files got past the parser. The 74 parse failures were
concentrated in a few constructs:

- BOSL2's header idiom `condition ? echo("...") true : true` (41 files)
- The `^` exponentiation operator (13 files)
- Identifiers starting with a digit, such as `12ptStar` and `8bit_polyfont`
  (6 files)
- Statement modifiers `#` and `%` (9 files)
- Trailing commas in vectors and calls (3 files)
- `each` and C-style `for` comprehensions (2 files)

Feature counts across the corpus also showed heavy use of `each` (50 files),
`echo` (65), `assert` (51), `is_undef` (55), function literals (27), dot
notation (42), and `lookup`/`search`/`rands` (11/26/8).

## Syntax compatibility slice

- Lexer/CST: added `^`, `#`, `undef`, digit-leading identifiers, exponent
  notation, leading-dot numbers, and node kinds for modifiers, `echo`/`assert`
  prefixes, `each`, dot notation, and C-style `for`.
- Parser: `^` binds tighter than unary minus and is right-associative; trailing
  commas; modifiers `*`, `#`, `%`, `!`; `undef`; dot notation; `echo`/`assert`
  expression prefixes; `each`; C-style `for` comprehensions; empty statements;
  standalone blocks as statements.
- Evaluator: `undef` (truthiness, arithmetic propagation, equality,
  `is_undef`), `^`, `echo`/`assert` as modules and expression prefixes,
  `Evaluation::messages`, `EvalError::Assertion`, `*` subtree disabling,
  `#`/`%`/`!` pass-through, `each`, C-style `for` with a 100,000-iteration
  guard, sequential `let` statements, dot and string indexing,
  `children([...])`, `version`/`version_num`, and `\x`/`\u`/`\U` string
  escapes.
- CLI prints collected `echo` messages.
- Added `scripts/check-scad-corpus.sh` to report the first failure per file
  across a directory tree.

## Collection value model

- Replaced numeric `Value::Vector` and `Value::Matrix` with one heterogeneous
  `Value::List`, so strings, booleans, `undef`, and deeper nesting can appear
  anywhere in a list.
- Generalized equality, truthiness, arithmetic, indexing, `len`, `concat`,
  `str`, and `echo` formatting to lists.
- Matched OpenSCAD edge semantics: list operations are elementwise and
  recursive, mixed list/scalar arithmetic is `undef`, and invalid indexes and
  unknown dot members are `undef`.
- Added `lookup`, `search`, and `rands`. `rands` is deterministic when no seed
  is supplied.
- Added 18 new tests: 2 value tests and 16 list integration tests.
- Updated the README, status, and language matrix.

## Lexical scope

- Replaced the `Vec<Scope>` stack with persistent `Rc<Env>` environments.
  Declarations store the environment they were defined in.
- Normal variables and declarations resolve through lexical parents at the
  definition site. `$` variables resolve through dynamic parents, preserving
  OpenSCAD's special-variable behavior.
- Module and function calls use the declaration environment as their lexical
  parent and the caller environment as their dynamic parent.
- `children()` evaluates call-site children with the caller as their lexical
  parent and the module body as their dynamic parent, so normal variables stay
  caller-scoped and `$` values such as `$parent_geom` remain visible.
- Function values capture their defining environment directly, so closures and
  returned function values no longer depend on the caller scope.
- Added tests for lexical module/function reads, dynamic `$fn`, nested module
  capture, and caller-scope `children()`.
- Corpus results are unchanged at this stage: 85 successful files, 3 language
  errors, 2 assertion failures, 2 geometry errors, and 17 other evaluation
  errors.

## Assignment and declaration hoisting

- Assignments are now collected per source file and block, evaluated in
  first-definition order, and use the last assignment to a name. Forward and
  self references therefore yield `undef`.
- Module and function declarations are registered recursively across `include`
  and `use` boundaries before a file executes, so `constants.scad` can call
  `ident()` even though `linalg.scad` is included later.
- Added 7 tests covering last-assignment-wins, first-definition order, forward
  and self references, module/block hoisting, and cross-include declarations.
- Corpus language errors dropped from 14 to 3. The remaining first errors moved
  deeper into arithmetic and library behavior (division by zero, missing
  hyperbolic functions, per-primitive `center`).

## Function literals

- Added `FUNCTION_LITERAL` and `INVOKE_EXPR` to the CST and parser. Function
  literals use the existing parameter-list grammar and can be nested or called
  immediately (`f(2)(3)`).
- Added `Value::Function`. Function values capture visible variables and user
  function declarations at creation, support positional/named/default
  arguments, can be passed, returned, and stored in lists, and can recurse
  when called from a scope where their name is visible.
- Added `is_function`; `str(function(x) x)` returns the literal source.
- Parse coverage over BOSL2 + MCAD is now 109/109. Full evaluation moved from
  73 to 85 successful files; the remaining language errors are mostly
  declaration ordering inside included BOSL2 files.
- Function literals capture visible variables when created; with assignment
  hoisting, later reassignments are already reflected in the captured value.

## Library search paths

- Angle-bracket `include` / `use` paths now search `OPENSCADPATH` and repeated
  `--library-path` directories, after the including file's directory.
- Quoted includes remain relative to the including file only.
- `EvaluationOptions::library_paths` carries explicit paths; the CLI and viewer
  initialize it from `OPENSCADPATH`.
- The corpus script defaults `OPENSCADPATH` to `.corpus` when pointed inside the
  pinned corpus.
- Corpus evaluation improved from 72 to 73 successful files; the 10 unresolved
  BOSL2/MCAD includes are gone. The next errors are mostly declaration ordering
  inside included BOSL2 files (`ident` used before `linalg.scad` is evaluated).

## Undef semantics

  OpenSCAD.
- Module and function parameters without defaults bind to `undef` when omitted.
- Removed `EvalError::UnknownIdentifier`; tests now assert `is_undef` behavior.
- Corpus evaluation moved from 35 to 72 successful files, and language errors
  dropped from 43 to 4. The remaining first errors are function literals

- Known immutable `each` now handles identifier-valued bodies (`[each v]`).
- Added a 256-scope call-depth guard so runaway recursion reports an error
  instead of overflowing the process stack.
