# Session notes — 2026-11-03

Trial of the [`monstertruck`](https://github.com/virtualritz/monstertruck) fork
on branch `wip/monstertruck`. Baseline for comparison is `main` at `f0cfaf2`.

## Why

Upstream `ricosjp/truck` accepts PRs slowly; `monstertruck` renames every crate
and carries its own boolean, meshing, healing, fillet, and STEP work. This branch
checks whether the fork can replace the vendored Truck stack without losing the
behaviour BrepSCAD relies on.

## API changes handled in `kernel-truck`

- `builder::tsweep` → `builder::extrude`; `builder::rsweep` →
  `builder::revolve` with `SweepAngle::{Closed, Partial(Rad)}`.
- `Surface::BSplineSurface` → `Surface::BsplineSurface`;
  `Surface::RevolutedCurve` → `Surface::RevolutionSurface`;
  `Curve::BSplineCurve` → `Curve::BsplineCurve`.
- `KnotVec` → `KnotVector`, `knot_vec()` → `knot_vector()`,
  `knot_vecs()` → `knot_vectors()`, `Plane::{u_axis, v_axis}` →
  `{axis_u, axis_v}`.
- Boolean ops return `Result<Solid, ShapeOpsError>` instead of `Option`; the
  adapter uses the native `difference` and falls back to the `*_normalized`
  entry points after its exact tolerance ladder.
- `Surface` gained `TsplineSurface`, `SphericalSurface`, and
  `ToroidalSurface`; the ray caster falls back to tessellation for those.

## Vendoring

Published `monstertruck-*` 0.4.1 compiles, but 36/38 `kernel-truck` unit tests
passed: cube-minus-sphere and the corner difference failed. The cause is that
`monstertruck-solid`'s default backend is "classic 0.3.2 verbatim", older than
the vendored Truck 0.4.0 pipeline and missing fixes the adapter needs.

The whole nine-crate kernel stack is therefore vendored from PR #31
(`pr/boolean-robustness`, `79ef869bc2`), which supplies the coplanar boolean
pipeline, 5-ray classification, normalized entry points, parallel face
division, and the meshing collision-culling fix. PR #32 (`1b6f1de61e`) is
applied on top for B-spline cuts near a knot.

Remaining BrepSCAD patches:

- `monstertruck-solid`: keep a divided face when `Face::try_new` rejects
  non-simple wires; snap an intersection parameter that lands on an existing
  vertex; return `Solid::new_unchecked` from `finalize` so open boolean results
  survive; fall back to the divided shells when `coplanar::sew` cannot stitch a
  pair.
- `monstertruck-topology`: preserve non-simple faces and open shells in
  `Shell::try_mapped` / `Solid::try_mapped`.

All 505 workspace tests pass. Details are in
[`../../vendor/README.md`](../../vendor/README.md).

## Analytic surface carriers

Monstertruck's two analytic carriers are now exported instead of tessellated:

- `Surface::SphericalSurface` uses the closed-form sphere path, including the
  processor's transform and orientation. A non-uniform scale would make an
  ellipsoid, so that case still falls back to tessellation.
- `Surface::ToroidalSurface` is exported as its exact homogeneous rational
  quadratic net through the existing spline tracer. Trim loops are projected
  with the analytic torus inverse map, swapped for an inverted processor, and
  scaled from `[0, TAU]` to the net's `[0, 1]` parameter range. `TrimRegion`
  gained a `v` period, mirrored in the CPU caster, GPU packing, and shader, so
  loops crossing the tube seam stay continuous.
- `Surface::TsplineSurface` is not tensor-product and still falls back to
  tessellation.

Our own primitives were already analytic: a revolved circular arc is detected
as a closed-form sphere and a revolved circle becomes an exact NURBS torus.
These carriers matter for imported geometry (STEP) and for any future kernel
path that emits them directly.

## Open questions

- The vendored stack is PR #31 plus PR #32, not a release. Re-check whether they
  have merged before depending on this long-term; if they do, switch the vendor
  source to the released version.
- `monstertruck-solid` defaults to the classic backend; its newer `integrate`
  pipeline is only compiled when `marching-ssi` is off, where it returns
  `NoBackend`. The branch keeps default features.
- `SphericalSurface` and `ToroidalSurface` are exercised by unit tests because
  the branch has no STEP importer yet; wire the importer up to use them on real
  data. T-splines still fall back to tessellation.
- `docs/status.md` and `docs/kernels.md` still describe the Truck stack. Update
  them only if this branch replaces `main`.
- The old `vendor/truck-*` trees and their patches are retained for comparison
  and switching back; they are not patched or compiled on this branch.
