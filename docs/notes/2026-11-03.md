# Session notes — 2026-11-03

Trial of the [`monstertruck`](https://github.com/virtualritz/monstertruck) fork
on branch `wip/monstertruck`. Baseline for comparison is `main` at `f0cfaf2`.

## Why

Upstream `ricosjp/truck` accepts PRs slowly; `monstertruck` renames every crate
and carries its own boolean, meshing, healing, fillet, and STEP work. This branch
checks whether the fork can replace the vendored Truck stack without losing the
behaviour BrepSCAD relies on.

## API changes handled in `kernel-truck`

- `builder::tsweep` → `builder::extrude`; `builder::rsweep` →
  `builder::revolve` with `SweepAngle::{Closed, Partial(Rad)}`.
- `Surface::BSplineSurface` → `Surface::BsplineSurface`;
  `Surface::RevolutedCurve` → `Surface::RevolutionSurface`;
  `Curve::BSplineCurve` → `Curve::BsplineCurve`.
- `KnotVec` → `KnotVector`, `knot_vec()` → `knot_vector()`,
  `knot_vecs()` → `knot_vectors()`, `Plane::{u_axis, v_axis}` →
  `{axis_u, axis_v}`.
- Boolean ops return `Result<Solid, ShapeOpsError>` instead of `Option`; the
  adapter maps them back to `Option` for its tolerance/retry ladder.
- `Surface` gained `TsplineSurface`, `SphericalSurface`, and
  `ToroidalSurface`; the ray caster falls back to tessellation for those.

## Vendoring

Published `monstertruck-*` 0.4.1 compiles, but 36/38 `kernel-truck` unit tests
passed: cube-minus-sphere and the corner difference failed. The cause is that
`monstertruck-solid`'s default backend is "classic 0.3.2 verbatim", older than
the vendored Truck 0.4.0 pipeline and missing fixes the adapter needs.

`monstertruck-solid` and `monstertruck-topology` are therefore vendored. Ported:

- `monstertruck-solid`: keep a divided face when `Face::try_new` rejects
  non-simple wires; snap an intersection parameter that lands on an existing
  vertex; skip boundary-less components during classification; port upstream
  0.4.0's orientation-aware `InsideJudge`; return `Solid::new_unchecked` from
  `finalize` so open boolean results survive.
- `monstertruck-topology`: preserve non-simple faces and open shells in
  `Shell::try_mapped` / `Solid::try_mapped`.

After those patches all 55 `kernel-truck` tests pass. Details are in
[`../../vendor/README.md`](../../vendor/README.md).

## Verification

- `cargo test --workspace`: green, 0 failures.
- `cargo clippy -p brepscad-kernel-truck --all-targets`: clean.
- `cargo fmt --check`: clean.
- SCAD corpus (`--evaluate`, 109 files): 93 ok, 3 language errors, 3 geometry
  errors, 1 kernel error, 5 other evaluation errors, 4 timeouts. The semantic
  results match the checked-in baseline; the only "regressions" are timeouts on
  files that now succeed but exceed the 8 s budget.

| --- | ---: | ---: | --- |
| `MCAD/bitmap/letter_necklace.scad` | 41.1 s | 32.7 s | kernel error → now ok |

| `BOSL2/tests/polyhedra.scad` | 6.75 s | 6.71 s | eval error |

So the corpus signal is not a semantic regression: two files are about 1.3× and
2.5× faster, but the default 8 s timeout records them as timeouts. Refresh the
baseline (or raise `CORPUS_TIMEOUT`) if this branch lands.

## Open questions

- `monstertruck-solid` defaults to the classic backend; its newer `integrate`
  pipeline is only compiled when `marching-ssi` is off, where it returns
  `NoBackend`. The branch keeps default features.
- `SphericalSurface` and `ToroidalSurface` fall back to tessellation in the ray
  caster. Our primitives still emit `RevolutionSurface`, so current scenes stay
  analytic; revisit when STEP import is wired up.
- `docs/status.md` and `docs/kernels.md` still describe the Truck stack. Update
  them only if this branch replaces `main`.
- The old `vendor/truck-*` trees and their patches are retained for comparison
  and switching back; they are not patched or compiled on this branch.
